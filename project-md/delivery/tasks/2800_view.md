# 2800: View

`thunderjar view` starts a local web page for browsing the run data store.

## Version bump type

patch

## Artifacts

- `thunderjar view [--data-dir <dir>] [--port <port>]`
- A Bun server with a small JSON API over the `RunDataStore`:
  - `GET /api/executions`: every execution, newest first
  - `GET /api/executions/:id`: the execution and its container runs, or a 404
- A client-rendered React app, served at `/`, with two pages:
  - the executions
  - one execution's container runs, with a column per measurement

## Example CLI Output

```
$ thunderjar view
Viewing /home/me/project/.thunderjar/.data
Open http://localhost:4300/
```

## Decisions

- The server reads the store through the `RunDataStore` interface. The store is now the SQLite store, which `view` reads through the same interface.
- The store is read afresh on every request, so a reload shows runs recorded since.
- Pages are routed by the URL's hash, so the server serves one page.
- The build now writes `dist/index.js` and the app's files beside it, so the bin moved from `dist/cli.js`.
  - Bun finds a bundled app's files relative to the working directory, not the bundle. So `view` changes into the bundle's folder before serving.
  - The package smoke test starts `view` and fetches the page's script, which fails without that.
